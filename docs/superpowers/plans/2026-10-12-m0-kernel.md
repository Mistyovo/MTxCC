# MTxCC M0 内核期 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付 MTxCC 内核：多 agent 渗透引擎（planner/worker 双图编排）+ per-task 容器沙箱 + RoE 双层围栏 + 审批门 + 流量留痕，能在本地靶场自主完成漏洞探索全流程。

**Architecture:** Go 单二进制（module `mtx`），内嵌 Next.js 静态前端与 SQL 迁移；分层单向依赖 `server → engine → agents → (harness, graph, tools)`、`tools → (sandbox, roe, guard, traffic)`。Agent 能力来自自建 harness（流式循环+工具并发+compaction+Settlement），编排经 PostgreSQL 探索图 CAS 解耦。

**Tech Stack:** Go 1.24+ / pgx v5 / testcontainers-go / tmux（shell 出）/ Docker SDK（moby） / go-mitmproxy（MIT 许可）/ Next.js 15 静态导出 / SQLite（modernc，纯 Go）。

**Spec:** `docs/superpowers/specs/2026-10-12-mtxcc-design.md`（本计划从该 spec 取值；执行者需同时读 spec 对应节）

## Global Constraints

- 依赖方向单向：任何包不得 import `internal/server`；单文件 >800 行为 CI 红线（lint 检查）。
- 严禁复制 `refer/` 下任何 GPL/AGPL 项目代码（概念借鉴允许）；新增依赖许可证必须 MIT/BSD/Apache-2.0/MIT 系。
- 所有 SQL 迁移幂等（`CREATE TABLE IF NOT EXISTS` 等），嵌入二进制（`go:embed`），启动时自动执行。
- LLM 三协议裸 HTTP 自实现（anthropic/openai/openai_responses），不用官方 SDK。
- 密钥落盘一律 AES-GCM（主密钥来自环境变量 `MTX_MASTER_KEY`，32 字节 base64）；日志/落盘前过脱敏器。
- UI 文案中文；API 路径与 JSON 字段英文。
- 测试可运行前提：本机 Docker（testcontainers）；无 Docker 时跳过集成测试（`-tags=dockerless` 编译通过仍必须）。
- 每任务一个 commit，消息格式 `feat|fix|test|chore(scope): ...`，结尾 `Co-Authored-By: Claude Code <noreply@anthropic.com>`。

## Review Focus

1. **RoE 绕过**（变量间接引用目标、域名 DNS 解析到 out-of-scope IP、尾点 FQDN `host.`）——期望：解析层拒绝或出口层兜底。测试钉在 Task 12（解析层表格用例）与 Task 15（egress 规则编译包含解析出的所有 IP）。
2. **CAS 双领竞态**——两个 worker 并发 ClaimIntent 同一意图，恰好一个成功。测试钉在 Task 2（事务级并发断言）与 Task 21（双 workerLoop 集成）。
3. **transcript 恢复的悬空 tool_use**——恢复会话时尾部存在无 tool_result 的 tool_use 导致 API 400。期望：Resume 清理后再发。测试钉在 Task 5。
4. **413 压缩循环**——压缩后仍超窗，Reactive 只重试一次并以 PromptTooLong 终态结束，不无限循环。测试钉在 Task 8。
5. **审批 ask 超时**——ask 60s 无人决定时默认 deny 且工具调用收到可读拒绝，引擎不阻塞后续轮次。测试钉在 Task 13（1s 超时注入加速）。
