# MTxCC M2 产品期 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 多用户 RBAC、审计链、升级机制、报告模板、完整文档——达到"干净 Ubuntu 上一键部署、2 小时内出首份合规报告"的产品标准。

**Architecture:** M0/M1 内核之上，补用户/权限/审计/升级四个产品面。全部接线到 server.New 产品装配。

**Spec:** `docs/superpowers/specs/2026-10-12-mtxcc-design.md` §3.1（users/audit_log）、§10（API+UI）、§14（交付）。

## Global Constraints
同 M0/M1；装配级验收为完成标准。

## Review Focus
1. RBAC：viewer 不得创建任务/编辑配置——测试钉 Task 1。
2. 审计链只增不改：UPDATE/DELETE 被拒——测试钉 Task 2。
3. 升级不丢数据：旧版 DB 在新版启动后 schema 兼容——测试钉 Task 4。
4. 报告模板可自定义且不破坏默认——测试钉 Task 5。
5. 无权限操作返回 403 而非 404（信息不泄漏）——测试钉 Task 1。

---

### Task 1: 多用户与 RBAC
Create: `internal/server/rbac.go`；Modify: auth.go（多用户登录）; Test: docker。
- users 表已有（M0 schema）；实现 `requireRole(roles...)` 中间件；admin 可 CRUD 用户；operator 可建/控任务；auditor 只读+审批；viewer 纯只读。
- 装配：全部 /api/* 路由按角色守卫。

### Task 2: 审计链
Create: `internal/server/audit.go`；Test: docker。
- 写路径（建任务/决策/用户变更/报告导出）→ INSERT audit_log（含 user/动作/目标/详情 jsonb）。
- DB 层 UPDATE/DELETE 被权限拒绝（专用只写角色）或应用层禁。

### Task 3: 报告模板
Create: `internal/report/template.go`；Test: unit。
- 模板变量注入（标题/公司/日期/扫描范围），默认模板兜底，自定义模板语法错不崩。

### Task 4: 升级机制
Create: `internal/store/version.go`；Modify: Dockerfile.mtx（入口 mtx migrate && mtx serve）。
- 迁移已幂等（M0 设计）；补：启动时打印 schema 版本；`mtx version` 子命令报版本+schema 号。
- 测试：旧 schema（仅 001）→ 跑 002 → 数据保留。

### Task 5: 完整文档
Create: `docs/` 快速开始/用户手册/API 参考/部署指南/安全白皮书/FAQ。

### Task 6: M2 验收
- 全套件绿 + RBAC 装配测试 + 审计写入测试 → tag `v0.3.0-m2`。
