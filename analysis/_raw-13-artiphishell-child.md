# artiphishell 子探索报告（原始素材，供 13 号报告整合）

> 来源：artiphishell 组的子 agent（Explore）交回的深度调研，父 agent 恢复后据此撰写正式报告。

Exploration of artiphishell (Shellphish AIxCC CRS) — 6 requested components. Repo root: `refer/04-competition/artiphishell/`. Shared infra: `libs/agentlib` (in-house agent framework on `langchain_core` + LiteLLM budget manager, `libs/agentlib/agentlib/lib/common/llm_api.py:11-56`), `libs/analysis-graph` (Neo4j graph), pydatatask (PDT) repos, `shellphish_crs_utils` models. Pipeline dataflow: povguy validates PoVs → poiguy converts crash reports to POI reports → patcherg orchestrates patch requests → patcherq/patchery generate patches → pov-patrol verifies mitigation → patcherg submits.

## 1. components/poiguy — POI extraction from crash reports (NOT LLM)
(a) Python, 294 LOC, single file `components/poiguy/poiguy.py`.
(b) Entry `__main__` at poiguy.py:249; `produce_poi_report()` (poiguy.py:34-123): parse `PoVReport` YAML → `RemoteFunctionResolver` → walk `dedup_crash_report.stack_traces[*].call_locations` → emit `POI(reason=crash_type, source_location=...)` for frames with resolved source not in the harness file (poiguy.py:63-87) → write `POIReport` JSON to `--output`.
(c) No LLM. "POI generation" is deterministic symbolization of stack traces.
(d) In: `--report` (PoVReport YAML from povguy), `--project-metadata`. Out: POIReport JSON consumed by patchers. Uses function-index service, OTEL spans.
(e) Graceful degradation: `generate_dirty_poi_report()` builds a partial report on any parse failure "to ensure that the pipeline can still progress" (poiguy.py:125-134, invoked at 273-283); `artiphishell_should_fail_on_error()` env switch toggles fail-fast vs continue.

## 2. components/pov-patrol — PoV↔patch mitigation checker (NOT LLM)
(a) Python, 393 LOC, `components/pov-patrol/pov_patch_check.py`.
(b) Entry `main()` (:356); two modes: `--mode pov` → `compare_pov_to_patches()` (:121) runs one crashing input against every patch; `--mode patch` → `compare_patch_to_povs()` (:271) tests one patch against all PoVs with a multiprocessing `Pool(3)` + `imap_unordered` (:324-328).
(c) No LLM. Mitigation = `oss_fuzz_project.run_pov(...)` produces no crash report (pov_patch_check.py:107-118).
(d) In: dedup PoV reports + crashing inputs + `patch_metadatas` (pipeline.yaml). Downloads patch build artifacts via `BuildServiceRequest.keyed_download_build_artifacts_tar` (PDClient) into `/shared/pov_patrol/<patch_key>` cache (:29-61); copies OSS-Fuzz project to tmp dir per test. Out: Neo4j edges `patch.mitigated_povs` / `patch.non_mitigated_povs` to `PoVReportNode`, plus `finished_pov_patrol`/`finished_patch_patrol` flags (:200-206, 337-343).
(e) Patterns: 3 retries with `signal.SIGALRM` per-task timeout (:248-266); idempotency via `is_connected()` checks before connecting edges; per-project shared artifact cache keyed by patch_key.

## 3. components/patcherq — main LLM patch agent (~7,135 LOC Python)
(a) Python; `src/patcherq/**` (agents, patch_generator, patch_verifier, toolbox, prompts as .j2).
(b) Entry `src/run.py` (argparse, `--patcherq_mode PATCH|SARIF|REFINE`, `--crs_mode full|delta`) → `patcherq/main.py:224 main()` → `PatcherQ.start()` triple-nested loop (main.py:90-194): outer **budget loop** → `RootCauseGenerator.reports()` (yields dyva/SARIF/triage root-cause reports one at a time) → inner **programmer feedback loop** `while programmer.patch_state != 'stop': generate(); verify()` (main.py:116-123).
(c) LLM via agentlib (`Agent`/`AgentWithHistory`, `LLMFunction`). Models: `programmer_llms=['claude-3.7-sonnet']`, `triage_llms=['claude-3.7-sonnet','claude-4-opus']` (src/patcherq/config.py:64-67); TriageGuy default gpt-4.1, 75 tool iters (agents/triageGuy.py:147-153); ProgrammerGuy claude-3.7-sonnet, 70 tool iters, temp 0.0, max_tokens 8192 (agents/programmerGuy.py:180-193); CriticGuy `o3` (agents/criticGuy.py:120); SARIFGuy/DiffGuy gpt-4o. ProgrammerGuy system prompt (prompts/programmerGuy/programmerGuy.CoT.system.j2:1-9): expert software engineer persona, edit buggy app to fix security vulnerability, root cause report provided, MUST NOT modify `LLVMFuzzerTestOneInput` entry points (:44). CriticGuy system prompt (prompts/criticGuy/criticGuy.system.j2:1-7): security expert patch validator — patch must not be easily bypassable, must not eliminate intended functionality (no premature returns).
Loop: plan (TriageGuy tool-using root-cause analysis) → act (ProgrammerGuy agentic code search/edit with peek_src/peek_logs/CodeQL/LSP tools) → verify (PatchVerifier: compile, build-pass, crash reproduction, unit tests, fuzz pass, CriticGuy review) → `set_feedback(failure_code, feedback)` re-invokes same ProgrammerGuy with templated failure feedback (utils/programmer.py:318-327, 461-784). Per-failure retry budgets: `max_programmer_total_attempts=11`, compile=4, crash=4, tests=2, duplicates=3 (config.py:43-50).
(d) In: PatchRequestMeta+POI report+crashing input (PATCH), SARIF file (SARIF), failing patch + bucket (REFINE); dyva root-cause reports; function index, CodeQL DB. Out: patch diff files + `PatchMetaData` YAML ("Writing the patch metadata to trigger patch patrol!", programmer.py:885-910), `GeneratedPatch.upload_patch` to analysis graph, optional SARIF, bypass requests (discoveryguy), libpermanence records, patched artifacts PDT repo.
(e) Notable patterns: (1) **structured-output repair** — `MyParser` regex-extracts `<patch_report>/<change><file><line><original><patched>` blocks; on failure calls cheap `gpt-4.1-mini` "format recovery" LLMFunction up to 3x (agents/programmerGuy.py:100-169). (2) **PatchCache memoization** — failed patch hashes cache replay "action" so duplicate LLM patches short-circuit verification (programmer.py:266-283). (3) **duplicate tool-call guard** — md5 of (tool,args) over last 3 calls returns `[ERROR]` "You performed the same tool call ... Just reuse the old results" (toolbox/peek_src.py:195-221). (4) **LLM fallback + nap** — on `LLMApiBudgetExceededError` rotate through `programmer_llms`, else sleep until next 7-min "budget tick" (up to 20 naps) (programmer.py:212-241, config.py:31-34). (5) temperature escalation (`increase_temperature_by`), failure-specific tool-set switching (programmerGuy.py:376-415), human-in-the-loop `chatline()` REPL for live debugging (programmerGuy.py:334-370).

## 4. components/patchery — one-shot LLM patcher (~5,775 LOC Python)
(a) Python package `components/patchery/patchery/` (generator, verifier, ranker, deduplicator).
(b) Entry `patchery/__main__.py` CLI (`--generate-aixcc-patch`, `--rank-patches`, `--deduplicate-patches`) → `Patcher.generate_verified_patches()` (patcher.py:279, ThreadPoolExecutor) → `_gen_and_verify_core()` retry loop `while len(patches) < max_patches and total_runs < max_attempts` (patcher.py:140-195): generate → `PatchVerifier.verify` → on success summarize + stop sibling threads (`first_patch_found` event, patcher.py:189-191); on failure feed `failed_patch` + verifier reasoning into next prompt. Verifier pass pipeline: Duplicate, NewCodeCheck, Compile, OssFuzzBuildCheck, AlertElimination, Regression, Functionality, SyzCaller, Fuzz (verifier/patch_verifier.py:32-42).
(c) LLM but **non-agentic one-shot** (no tools): `post_llm_requests()` → agentlib `LLMFunction.create` against LiteLLM gateway (`AIXCC_LITELLM_HOSTNAME`, provider budgets `claude-budget`/`openai-budget`, generator/llm_utils.py:51-175); default `claude-3.7-sonnet` (aicc_patcher.py:32), thinking `{"type":"enabled","budget_tokens":10000}` for Claude, `reasoning_effort` for o-series (llm_utils.py:26-47); ordered model-fallback chain + "Budget reset per 30 mins, retry it" (llm_utils.py:133-147). Two-stage prompting: `SUMMARIZE_REPORTS_PROMPT` infers bug type first (generator/prompts/one_shot_prompts.py:237-264, incl. "For Java Projects, be vigilant for backdoor vulnerabilities intentionally injected into the code"), then `THREE_EXPERTS_PROMPT` (one_shot_prompts.py:282-294): society-of-mind three-experts peer-scoring debate in a single completion; also "If your patch is accepted, you will be rewarded with a flag. / Please think carefully or a human will be physically harmed." (:301-302).
(d) In: PoI clusters + function source (kumushi `Program`), sanitizer reports, git diffs; Out: `Patch` objects with summaries, ranking/dedup of patch dirs, analysis-graph uploads.
(e) Patterns: **temperature heat schedule** — temp rises to 0.1 after half the attempts plus verifier `failure_heat` penalty, capped 0.5 (patcher.py:97-117,156-162); fuzzy SEARCH/REPLACE parsing with whitespace-normalized substring match and indentation preservation (llm_utils.py:230-265); regenerate up to 3x on format errors (llm_patch_generator.py:375-380); Claude-specific message ordering workaround (:366-372); RAG patch example slot (kernel `kmalloc_reserve` diff, one_shot_prompts.py:3-95).

## 5. components/patcherg — patch orchestration/"emperor" (NOT LLM, 1,261 LOC)
(a) Python, effectively one file `components/patcherg/patcherg/__main__.py` (1,199 lines).
(b) Entry `run()` infinite ~30s loop, logs "Starting emperor" (:944-947): `find_clusters()` of PoV reports in Neo4j analysis graph → maintain `BucketNode`s (bucket_key = md5 of sorted organizer dedup identifiers, :972-973) → `process_bucket()` issues patch requests → `select_patches_to_submit()` / `select_harness_inputs_to_submit()` yield submissions.
(c) No LLM. Scoring: `bayesian_likelihood_score(k,n) = (k+1)/(n+2)` Beta(1,1) posterior mean of mitigation probability (:113-133, applied at :95-111) — docstring notes "50/50 (0.981) > 49/50 (0.962) > 3/3 (0.800)".
(d) In/out: reads `GeneratedPatch`/`PoVReportNode`/`PatchergSubmissionNode` from analysis graph; writes `PatchRequestMeta` YAML files consumed by patcherq (:708-722), patch bypass requests, patch/crash "submission edict" files for the submitter; uses PDClient, `DEADLINE` (ms epoch) env.
(e) Patterns: **endgame strategy** — "perfect" patches (mitigate all PoVs in cluster) submitted only after an age timeout, imperfect ones held until within `NON_PERFECT_PATCH_SUBMISSION_TIMEOUT_MINUTES` of deadline then "NO TIME LEFT! NOW OR NEVER!" (:506-628); explicit distrust of patchery-only solutions (skipped unless endgame, :536-545); only oldest-best patch per bucket; adaptive submission timeout growing `1.5 + 0.2*log2(1+extra)` with cluster count (:81-93); acknowledged race condition with submitter's `submitted_time` (:585-588).

## 7. components/povguy — PoV validation harness (NOT LLM, 654 LOC)
(a) Python: `povguy.py` (476), `verify_base_run.py` (89), `verify_build_check.py` (89).
(b) Entry `main()` (povguy.py:415-476) → `run_pov()` (:63-412): build runner image (Jazzer LOSAN instrumentation for JVM, :91-94) → run candidate PoV `retry_count=5` times, intersecting triggered sanitizers across runs and accumulating stack traces seen in any run (:120-184) → reject if no consistent sanitizer / no significant crash / no useful stack traces (:203-227) → delta mode: rsync base source to tmp and re-run unpatched base; crash there exits(0) ("See what to do here as this could possibly be a zero day", :283-290) → write dedup + representative + LOSAN outputs, upload `HarnessInputNode` + `PoVReportNode` to graph (:232-359).
(c) Not LLM-driven despite `init_llm_otel()` at :44 — purely deterministic execution/validation.
(d) In: candidate PoV file + `--base-meta-path` YAML; Out: per-crash full report, dedup PoVReport (md5-keyed), representative crash input/metadata, LOSAN variants (10 output paths, :423-433); graph nodes; on base failure queries `PDT_AGENT_URL /data/verify_base_runs/base_run_success/<harness_info_id>` (:303-322).
(e) Patterns: sanitizer-set intersection across runs for flakiness filtering with early break (:169-170); cross-run stack-trace union backfill (:177-184); `clean_invalid_utf8` (:350-353); MD5 crash-report dedup key (:345-346); exit(0) on rejected PoVs so pipeline doesn't retry.
